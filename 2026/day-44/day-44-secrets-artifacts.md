## Task 1 – GitHub Secrets

Created a repository secret named:

`MY_SECRET_MESSAGE`

The workflow checked whether the secret was available without printing its actual value.

The workflow output:

```text
The secret is set: true
```

### Why should secrets never be printed in CI logs?

Secrets may contain sensitive information such as passwords, access tokens, API keys, and credentials. Exposing them in CI logs can create a security risk and potentially allow unauthorized access to systems or services.

GitHub Actions automatically masks registered secret values in logs, but secrets should still never be intentionally printed.

## Task 2 – Use Secrets as Environment Variables

Passed the GitHub secret to a workflow step as an environment variable:

```yaml
env:
  SECRET_MESSAGE: ${{ secrets.MY_SECRET_MESSAGE }}
```

The secret was accessed through the shell environment without hardcoding the secret value in the workflow.

The workflow verified that the environment variable was available without displaying the actual secret.

## Task 3 – Upload Artifacts

Created a test report during the workflow:

`test-report.txt`

The file was uploaded using:

```yaml
uses: actions/upload-artifact@v4
```

The artifact was successfully generated and made available from the GitHub Actions workflow run.

### Artifact Workflow

```yaml
- name: Generate Test Report
  run: |
    echo "Day 44 Test Report" > test-report.txt
    echo "All tests passed successfully." >> test-report.txt
    echo "Generated by GitHub Actions." >> test-report.txt

- name: Upload Test Report
  uses: actions/upload-artifact@v4
  with:
    name: test-report
    path: test-report.txt
```

### Artifact Verification

The `test-report` artifact was successfully uploaded and downloaded from the GitHub Actions run.

## Task 4 – Download Artifacts Between Jobs

Created two jobs:

```text
generate → consume
```

The `generate` job created and uploaded an artifact.

The `consume` job downloaded the artifact from the previous job and printed its contents.

### Download Artifact

```yaml
- name: Download Artifact
  uses: actions/download-artifact@v4
  with:
    name: job-output
```

The downloaded file contained:

```text
Hello from Job 1
This file was created in the generate job.
```

### Real-World Use of Artifacts

Artifacts can be used in real CI/CD pipelines to store and transfer:

- Build packages
- Test reports
- Application binaries
- Logs
- Deployment packages
- Generated documentation

They are especially useful when one job produces an output that another job needs.

## Task 5 – Run Real Tests in CI

Created a Python script:

`test_script.py`

The script contains a simple function and test:

```python
def add(a, b):
    return a + b


result = add(10, 20)

if result == 30:
    print("Test passed")
else:
    print("Test failed")
    exit(1)
```

Created a GitHub Actions workflow that:

1. Checks out the repository
2. Sets up Python
3. Runs the Python script
4. Fails the pipeline if the script exits with a non-zero status

### Passing Test

The CI workflow successfully produced:

```text
Test passed
```

The workflow completed successfully with a green status.

### Intentional Failure

To verify CI failure handling, I intentionally changed the test to:

```python
result = add(10, 25)
```

The GitHub Actions workflow correctly failed and showed a red pipeline.

After fixing the test back to:

```python
result = add(10, 20)
```

the workflow successfully became green again.

This confirmed that the CI pipeline correctly detects failed tests.

## Task 6 – Caching

Added `actions/cache@v4` to cache the Python pip directory:

```yaml
uses: actions/cache@v4
with:
  path: ~/.cache/pip
  key: ${{ runner.os }}-pip-${{ hashFiles('**/requirements.txt') }}
  restore-keys: |
    ${{ runner.os }}-pip-
```

The workflow was executed twice.

During the second run, the cache was successfully restored.

The GitHub Actions log showed:

```text
Cache restored successfully
Cache restored from key: Linux-pip-
```

### What is being cached?

The workflow caches:

```text
~/.cache/pip
```

This directory contains cached Python package files downloaded by pip.

### Where is it stored?

The cache is stored and managed by GitHub Actions and can be restored by later workflow runs when the cache key matches.

Caching helps avoid downloading the same dependencies repeatedly and can improve CI workflow performance.

## Key Takeaways

✔️ GitHub Secrets provide a secure way to store sensitive values used by CI/CD workflows.

✔️ Secrets should never be intentionally exposed in CI logs.

✔️ Secrets can be passed to workflow steps through environment variables.

✔️ Docker credentials should be stored as GitHub Secrets rather than hardcoded in workflows.

✔️ Artifacts allow generated files to be stored and downloaded after a workflow run.

✔️ Artifacts can be transferred between different jobs.

✔️ `needs:` can be used to control dependencies between jobs.

✔️ CI pipelines should fail when tests return a non-zero exit code.

✔️ Intentionally breaking a test is a useful way to verify that CI failure handling works correctly.

✔️ Caching dependencies can reduce unnecessary downloads and improve workflow efficiency.

✔️ `actions/cache@v4` can be used to cache dependency directories.
